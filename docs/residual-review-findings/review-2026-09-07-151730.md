## findings

### F1 — Correctness — P1 — blocks merge
- reviewer: "Correctness"
- verdict: FAIL
- finding: `sketch_v2.js` `handleInput()` calls `particle.move(moveSpeed)` without the
  world-dimension args → `Particle.move` falls back to `Number.POSITIVE_INFINITY` bounds
  (`particle.js:57`) → the player walks out of the world entirely. Border walls only block
  rays, not movement. Camera offset goes negative, scene renders empty gradient, user must
  walk back or press R. v1 clamps (world bounds + collision); v2 does not.
- evidence: `sketch_v2.js` `handleInput()` → `particle.move(moveSpeed)` / `particle.move(-moveSpeed)`;
  `particle.js:61-72` shows clamping only when finite bounds are passed.
- autofix-class: A (pass `worldW, worldH` to both `move` calls)

### F2 — Data migration — P2 — can merge with follow-up, but should fix now
- reviewer: "Data migration"
- verdict: FAIL
- finding: `sketch_v2.js:20` reuses `SETTINGS_STORAGE_KEY = 'ray-casting-settings-v1'`,
  identical to v1 (`sketch.js:25`). v2 save (`Ctrl+S`) overwrites v1's settings blob and
  vice versa. Read path is tolerant (`Number.isFinite` guards, wall filter), so no crash —
  but the two apps clobber each other's saved state. All other v2 DOM/classes are `v2-`-prefixed;
  the storage key is the one naming inconsistency.
- autofix-class: A (change to `'ray-casting-settings-v2'`)
